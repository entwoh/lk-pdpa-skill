# Personal Data Breach Response Plan
දත්ත කාන්දු වීමකදී ක්‍රියා කළ යුතු ආකාරය · தரவு மீறல் ஏற்படும்போது செய்ய வேண்டியவை

**Law:** PDPA s.23 (operational 1 Jan 2027). The controller **must notify the DPA**; the timing, form, content and when to notify affected people will be set by **DPA rules** (draft rules published Oct 2024 — not final). **The Act sets no hour limit.** Until final rules: notify promptly and document everything. (GDPR's 72-hour rule is a useful international benchmark, not Sri Lankan law.)

"Personal data breach" = any act or omission causing accidental or unlawful destruction, loss, alteration, unauthorised disclosure of, or access to, personal data (s.56).

## Step 1 — Contain (first hours)
⬜ Stop the leak (disable account, revoke keys, isolate server, recall email)
⬜ Preserve evidence (logs, screenshots) — don't wipe systems
⬜ Inform the DPO / privacy lead and management

## Step 2 — Assess
| Question | Answer |
|---|---|
| What happened, when discovered, when started? | |
| What data? Any special categories (health, biometric, children, financial)? | |
| How many people? | |
| Was data encrypted? | |
| Likely harm (fraud, identity theft, discrimination, distress, physical danger)? | |
| Processor involved? (processor must cooperate — s.22) | |

## Step 3 — Notify
⬜ **DPA** — per s.23 and current DPA rules · info@dpa.gov.lk · +94 11 269 7241
⬜ **Affected people** — when DPA rules require, or when harm is likely (good practice). Plain language; what happened, what data, what we did, what they should do (e.g. change password, watch bank statements), contact point. Use their language (SI/TA/EN).
⬜ **Sri Lanka CERT** (https://cert.gov.lk) for cyber incidents · **Police** for crimes · sector regulator (e.g. CBSL) if their rules require
⬜ Insurer, if cyber insurance

## Step 4 — Fix & learn
⬜ Root cause · ⬜ fix controls · ⬜ update DPIA/DPMP · ⬜ staff briefing
